# ADR 0001 — Expo (React Native + TypeScript + Expo Router) for Android and web

- **Status:** Accepted
- **Date:** 2026-09-03

## Context

The deck needs a single application that runs offline on Android and in modern web
browsers, sharing the navigation model, design system, and domain logic. An earlier
web-only scaffold (Vinext/Cloudflare) was interrupted and uncommitted.

## Decision

Build on **Expo + React Native + TypeScript**, with **Expo Router** for both targets.

- One codebase, shared routes, design system, and domain layer.
- Native Android packaging via EAS Build; responsive static web output via
  `expo export --platform web`.
- Platform differences (storage, haptics) are isolated behind `*.native.ts` /
  `*.web.ts` files: `expo-sqlite` on Android, IndexedDB on web.

## Consequences

- **Positive:** single source of truth; offline-first; URL-addressable web routes;
  strong touch/gesture/accessibility support; native web fallback not required.
- **Neutral:** the deck bundle is immutable app content committed as JSON + optimized
  JPEG art (~21 MB) rather than parsed from DOCX at runtime.
- **Negative:** native-only features (haptics, share sheets) need small platform
  adapters; EAS Build is required to produce an Android binary.
